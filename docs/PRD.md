## 1. 需求背景

平台 26.2 万会员中 76% 处于流失边缘（R=1），30 天复购率基线 42.3%，流失用户平均生命周期仅 21.7 天。分析报告已产出预警人群识别规则（P50~P90 分位数，首批命中 44,295 人）、品类关联规则（Top 10 强组合）及流失预测模型（AUC 0.77）。

**当前运营工作存在三个问题**：圈人靠手工提数、券与推荐规则无法沉淀复用、策略效果无法验证。

**产品定位**：本产品为运营端营销策略平台（To B），提供"圈人 → 配策略 → 执行触达 → 效果回收"全流程能力。App 推荐位、消息推送等 C 端展示仅为下游触达通道，由客户端团队实现，本文档不涉及 C 端界面设计。

**成功指标**：

| 指标 | 基线 | 目标 |
| --- | --- | --- |
| 30 天复购率 | 42.3% | +2pp 以上（AB 实验验证） |
| 圈人到下发耗时 | 人工约 2 天 | 平台配置 30 分钟内 |
| 实验数据获取 | 人工提数半天 | 看板实时可查 |

## 2. 名词定义

| 名词 | 定义 |
| --- | --- |
| 预警人群 | 距上次购买天数处于品类 P50~P90 区间的用户 |
| 人群包 | 按规则圈选并固化的用户集合，有唯一 ID 与快照 |
| 策略 | 人群包 + 触发规则 + 动作（发券/推荐）+ 触达通道的组合 |
| 唤回率 | 30 天内下单人数 / 组内总人数（即 30 天复购率） |
| ROI | 策略带来的增量 GMV / 券成本 |

## 3. 功能需求

### 3.1 功能架构

母婴零售用户运营策略平台
├── M1 人群圈选：标签圈人 / 预警人群自动圈选 / 人群包管理
├── M2 策略配置：券规则 / 推荐规则 / 文案模板
├── M3 执行触达：跑批任务 / 下发引擎 / 触达通道对接
├── M4 效果监控：AB 实验管理 / 实验看板
└── M5 用户 360：用户详情 / 策略命中记录


### 3.2 M1 人群圈选

#### 3.2.1 圈人方式

| 方式 | 规则说明 | 优先级 |
| --- | --- | --- |
| 标签圈人 | 多标签组合筛选：生命周期阶段（孕育期/育儿期）、RFM 分层、宝宝年龄、省份、累计消费区间、客户状态（活跃/沉默/预流失/流失）。多标签间支持 AND / OR | P0 |
| 预警人群自动圈选 | 每日跑批按 3.2.2 规则自动生成并更新人群包 | P0 |
| 人群包管理 | 人群包可保存、复制、二次编辑、查看人数快照；支持命名与备注 | P1 |

#### 3.2.2 预警人群计算规则（P0）

- 计算逻辑：`距上次购买天数 ∈ [品类P50, 品类P90]` 且 `近90天未收到同品类券`。
- 初始阈值（来源：分析报告 14.2；P50/P90 由复购周期模型每日重算，自动更新）：

| 品类 | P50 | P90 |
| --- | --- | --- |
| 零辅食 | 157 天 | 299 天 |
| 奶粉 | 172 天 | 304 天 |
| 尿裤 | 177 天 | 302 天 |

- "距上次购买天数"按 T-1 实时计算。
- 剔除规则：已注销用户、黑名单用户自动剔除并写入日志。

#### 3.2.3 圈选结果列表页

| 字段 | 说明 |
| --- | --- |
| 用户昵称/编号 | 手机号脱敏展示（如 138****1290） |
| 宝宝年龄 / 生命周期阶段 | 来自会员画像 |
| 累计消费 / 消费订单数 | 来自订单模型 |
| 偏好品类 | Top 1~3 品类 |
| 客户状态 | 活跃 / 沉默 / 预流失 / 流失 |
| 命中策略 | 命中的策略名称，无则显示"—" |
| 预警等级 | 展示"距上次购买 N 天 + 区间进度条"，如 `235 天 ▓▓▓▓░░ [157-299天]` |

- 筛选与排序：支持按客户状态、生命周期、预警等级筛选；支持搜索昵称/电话/宝宝昵称。
- 空态：无结果时展示"未找到符合条件的人群，请调整筛选条件"。

#### 3.2.4 用户详情页（跳转）

- 点击列表行进入用户 360 详情（见 3.6）。

### 3.3 M2 策略配置

#### 3.3.1 券规则配置（P0）

| 配置项 | 类型 | 说明与约束 |
| --- | --- | --- |
| 策略名称 | 文本 | 必填，≤ 20 字 |
| 触发品类 | 单选 | 奶粉 / 尿裤 / 零辅食 |
| 触发条件 | 选择 | 距上次购买天数 > P50（默认跟随分位数模型，支持手动覆盖并标记"手动"） |
| 券类型与力度 | 选择 | 满减券：门槛 + 面额。初始规则见下表 |
| 券有效期 | 数字 | 发放后 24~168 小时，默认 48 小时 |
| 营销预算上限 | 金额 | 单策略发放总额上限；达到 90% 预警，达到 100% 暂停发放并通知创建人 |
| 叠加规则 | 开关 | 默认不可与其他券叠加 |
| 限领规则 | 固定 | 单用户单品类限领 1 张 |

初始券规则（来源：分析报告 14.2，可修改）：

| 品类 | 券种 |
| --- | --- |
| 零辅食 | 满 50 减 5 |
| 奶粉 | 满 200 减 20 |
| 尿裤 | 满 100 减 10 |

#### 3.3.2 推荐规则配置（P1）

- 配置维度：触发品类 → 推荐品类 + 推荐理由文案。
- 数据来源：品类关联规则表，仅允许配置**提升度 > 1.5 且置信度 > 30%** 的组合（系统自动过滤，规则来源见分析报告 15.2）。
- 禁配规则：提升度 < 1.5 的组合（如奶粉→尿裤，提升度 1.42）不允许保存，保存时报错提示。
- 输出：向触达通道输出 `用户ID + 推荐商品池（Top N）+ 推荐理由`，展示形式由下游实现。

初始推荐规则：

| 触发品类 | 推荐品类 | 置信度 |
| --- | --- | --- |
| 营养品 | 零辅食 | 43.6% |
| 喂养用品 | 零辅食 | 39.7% |
| 喂养用品 | 纺织品 | 35.4% |
| 玩具车床图书 | 零辅食 | 34.9% |

#### 3.3.3 文案模板（P1）

- 支持新建/编辑/停用文案模板，支持变量：`{昵称}` `{品类}` `{券面额}` `{有效期}`。
- 变量在发送时自动替换；变量缺失时该用户跳过发送并记日志。
- 初始模板：

| 场景 | 模板 |
| --- | --- |
| 复购唤醒 | 您的宝宝口粮快吃完啦，专属优惠已到账 |
| 交叉推荐 | 买过{品类}的妈妈，30%也选择了{推荐品类} |
| 唤回 | 好久不见，为您准备了专属大额券 |

### 3.4 M3 执行触达

#### 3.4.1 任务触发

- 定时跑批：每日 02:00 更新预警人群包 → 匹配生效中的券策略 → 生成待下发队列。
- 手动触发：人群 ≤ 5,000 人时支持"立即执行"；> 5,000 人仅支持定时下发。
- 下发方式：立即执行 / 定时下发（指定日期时间，精确到分钟）。

#### 3.4.2 触达通道

| 通道 | 用途 | 优先级 |
| --- | --- | --- |
| App 推送 | 券到账通知、推荐触达 | P0 |
| 短信 | App 推送失败/无推送权限的降级通道 | P1 |

#### 3.4.3 触达频控

- 同一用户单日最多触达 1 次，7 天内最多 2 次。
- 触达时机默认在访问高峰（10:00 / 15:00 / 20:00）中就近选择。

#### 3.4.4 异常处理

| 场景 | 处理 |
| --- | --- |
| 推送失败 | 重试 2 次（间隔 1 小时），仍失败降级为短信（P1）；短信也未配置则记失败日志 |
| 推荐商品下架 | 兜底推荐同品类热销 Top 10 |
| 预算达到上限 | 暂停该策略发放，站内通知策略创建人 |
| 用户退订 | 写入退订名单，全通道永久停发 |
| 用户注销 | 任务执行前剔除，记日志 |

### 3.5 M4 效果监控与 AB 实验

#### 3.5.1 实验创建（P0）

创建流程（分步表单）：

1. 选择人群包（只读展示人数快照）；
2. 配置分组：分组数 2~3，每组策略从已生效策略中选择，对照组策略为"不干预"；分流比例可调，合计 100%；
3. 分流机制：按 UserId 尾号哈希随机分流（固定选项，一期不做其他机制）；
4. 配置观测指标与实验周期（默认 45 天）；
5. 提交后实验进入"进行中"，配置锁定不可改（如需修改需终止重建）。

校验规则：

- 每组人数 ≥ 500，否则阻断提交并提示"样本量不足，建议扩人群或减少分组"；
- 同一用户同一时间只能属于一个进行中的实验。

#### 3.5.2 首期实验配置（初始化预置）

- 人群：R=1 且 F=5 高价值流失用户，约 2,600 人（口径见分析报告 10.2）。

| 组 | 比例 | 策略 |
| --- | --- | --- |
| A（对照） | 50%（1,300 人） | 不干预 |
| B（实验 1） | 25%（650 人） | 发 20 元券 |
| C（实验 2） | 25%（650 人） | 发 10 元券 |

> 样本量说明：2,600 人为分析报告既定总体，检验效力有限；如需达到 1,500 人/组的理想样本量，可扩展至预警人群 44,295 人。此说明写入实验详情页"备注"字段。

#### 3.5.3 实验看板（P0）

**页面结构**：

1. **实验概览**（4 指标卡）：实验进度（第 N 天/总天数）、各组人数、剩余观察天数。
2. **分组对比表**：

| 指标 | 计算 | 说明 |
| --- | --- | --- |
| 唤回率（主指标） | 30 天内下单人数/组人数 | 数据 T+1 更新 |
| 客单价 | 组内 GMV/订单数 | — |
| ROI | 券带来 GMV/券成本 | 对照组不展示 |
| 退货率 / 客诉率 | — | 护栏指标，高于基线标红 |

3. **显著性标识**：主指标组间差异 p<0.05 时，展示绿色"已显著"标签；未显著展示灰色"观察中"。
4. **趋势图**：各组唤回率每日折线（D0 至今日）。
5. **结论卡片**：满足判定规则（见 3.5.4）后自动生成结论文案，附按钮【生成实验报告】【发起全量申请】。

#### 3.5.4 判定与操作

- 判定规则（系统自动标注，人工决策）：
  - 显著性：主指标 p<0.05；
  - 有效性：实验组唤回率 > 对照组，且护栏指标未恶化；
  - 力度优选：多实验组均有效时，取 ROI 最高者。
- 操作：全量 / 迭代券力度 / 终止实验，均需运营负责人角色在平台内审批，审批记录留痕。

#### 3.5.5 实验列表页

- 展示字段：实验名称与编号、策略类型、人群规模、分组机制、运行状态（进行中/已锁定/已结束）、核心指标差异、负责人、操作（详情/暂停/归档）。
- 已结束实验可查看归档报告。

### 3.6 M5 用户 360 视图

- 基础信息：会员属性、宝宝档案（昵称/月龄/生日）、生命周期阶段、RFM 标签。
- 订单消费历史：订单列表（订单号/时间/商品/金额/门店/状态）。
- 行为时间线：咨询、购买、互动事件按时间倒序。
- **策略命中记录（本期新增）**：命中的策略名称、收到的券、推荐商品、领用/核销状态、触达时间与通道。

## 4. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 圈选结果查询（≤5,000 人）响应 ≤ 3s；每日跑批须在 02:00–05:00 窗口完成，超时告警 |
| 权限 | 角色：运营（圈人/配置/下发）、负责人（审批/全量/预算）、数据（看板只读）；全量下发与预算修改需二次确认 |
| 数据安全 | 手机号等敏感字段脱敏；人群包导出需负责人审批；导出记录留痕 |
| 审计 | 策略创建/修改/下发/审批全操作日志，保留 ≥ 1 年 |
| 可用性 | 跑批失败自动告警并支持手动重跑；策略下发支持一键暂停 |

## 7. 数据口径说明

1. 订单数据为 2021-01-01 至 2021-12-31 快照，原始 826,000 条，清洗后有效订单 798,277 条；会员 261,959 人。
2. 分析报告中的"距今天数"为距数据截止日（2021-12-31）口径；平台上线后统一为 T-1 实时计算。

4. 初始券规则与推荐规则为分析报告结论的快照，均支持运营后台修改。
